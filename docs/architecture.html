01

总体架构图

7 层主链路垂直贯穿：Customer → Plane → GitLab → Jenkins → Build Infrastructure → Nexus → Deployment。GitLab 右侧分出 RagFlow 知识检索分支，AI Agent 作为横向智能层（紫色虚线）贯穿所有系统。底部为职责边界矩阵与流向图例。

02

Customer / Plane / GitLab 组织模型

业务维度 → 项目管理 → 代码组织的三层映射。Customer 与 Product 严格分离：客户项目通过 Configuration → Plugin → Extension → Customer Project 复用通用产品，不复制代码。底部展示 Plane ↔ GitLab 追溯链。

03

Jenkins + Build Agent + Nexus CI/CD 流程

project.yaml 驱动 Jenkins 全流程决策；8 个 Build Agent 矩阵按 Customer/Stack Label 动态调度；Nexus 双流（依赖流拉取 + 制品流推送）分离；SaaS 自动部署与客户现场离线包双路径；底部为 Artifact 全链路可追溯元数据。

04

GitLab + RagFlow AI Knowledge 流程

GitLab docs/ 作为技术知识 Source of Truth，同步至 RagFlow 经 Parse → Chunk → Embedding → Index → Retrieval 形成 AI Assistant。知识按 Customer / Product / Repository 三维组织，检索权限与 GitLab Group/Project 对齐。RagFlow 是检索层，非原始存储。

05

AI Agent 驱动的软件研发闭环

Requirement → Planning → Coding → Build → Deploy → Feedback 六步闭环，AI Agent 紫色虚线外框包裹全程，右侧弯曲箭头从 Feedback 回到 Requirement。底部为四类能力矩阵与权限约束——AI Agent 不超越用户授权。

06

系统职责边界矩阵

六大核心系统的职责边界——每个系统管什么、不管什么，一目了然。这是整套架构的"宪法"。

Plane

= What / Why · 项目管理 / 工作管理系统
Project · Requirement · Issue · Task · Sprint · Milestone · Roadmap · Progress · Work Assignment · Product Planning

不作为代码仓库 · 不作为技术文档 Source of Truth

GitLab

= Code / Technical Knowledge · Source of Truth
Git Repository · Group/Subgroup/Project · Branch · Tag · MR · Code Review · Issue · Release · Documentation · Metadata · Build/Deploy Config

不做制品中心（由 Nexus 负责）

Jenkins

= How · CI/CD Orchestrator
Pipeline · Build · Test · Package · Artifact Promotion · Deployment · Build Agent Scheduling · Docker Build

不做代码存储 · 不做制品存储

Nexus

= What was built · Dependency + Artifact Repository
Third-party Proxy · Dependency Cache · Internal Packages · Build/Release Artifacts · Docker Registry · NuGet · Maven · npm · Generic

Artifact Source of Truth · 不与 GitLab 重复

RagFlow

= What we know · AI Knowledge Retrieval Layer
Document Parsing · Indexing · Chunking · Embedding · Retrieval · Knowledge Base · AI Q&A

不作为原始文档存储系统（GitLab 才是）

AI Agent

= Intelligent Worker · Cross-system Automation
Requirement Analysis · Issue Creation · Code Search/Gen · MR Creation · Build/Log Analysis · Doc Generation · Knowledge Retrieval

横向连接各系统 · 不超越用户权限
07

核心设计原则

20 条核心设计思想，贯穿整套架构。从职责分离到全链路可追溯，从 AI-friendly 到权限约束。

1Plane 管项目和需求，GitLab 管代码和技术知识，职责不混
2Jenkins 管自动化执行，Nexus 管依赖和制品，各司其职
3RagFlow 管知识检索，不做原始存储，GitLab 才是 Source of Truth
4AI Agent 横向连接整个研发流程，跨系统自动化
5Git Repository 是项目技术知识 Source of Truth
6Nexus 是 Artifact Source of Truth
7Customer 与 Product 分离，客户项目不复制产品代码
8通用能力优先通过 Configuration / Plugin / SDK 实现
9Build Agent 根据 Customer / Project / Technology Stack 选择
10Build Environment 可追踪，记录 Agent / 工具链版本
11Artifact 可追踪，含 Commit / Build / Agent / Dependencies
12Deployment 可追踪，知道什么版本部署到哪里
13AI 检索遵循用户权限，不绕过 GitLab 权限模型
14project.yaml 驱动 Jenkins 全流程决策
15Nexus 双流分离：依赖流拉取 + 制品流推送
16双部署路径：SaaS 自动 + 客户现场离线包
17Docker Build 是 Pipeline 的 Build Strategy，非独立 CI
18文档与代码同版本控制，Markdown/YAML/Mermaid 优先
19关键工程信息结构化、版本化、AI-friendly
20完整 DevOps + AI SDLC 闭环：Customer → Knowledge → AI Automation
